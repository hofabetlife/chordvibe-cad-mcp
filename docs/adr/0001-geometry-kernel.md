# ADR-0001: Выбор геометрического ядра для `mcp-cad-core`

- **Статус:** Proposed (`[DECISION]` — ожидает утверждения архитектором)
- **Дата:** 2026-11-05
- **Задача:** `P1-T3` (вход для `P1-T4`, `P2-T5..T8`, `P3-T5`, `P3-T11`)
- **Прототипы (Spikes):** [`spikes/manifold_rust/`](../../spikes/manifold_rust/README.md), [`spikes/monstertruck_brep/`](../../spikes/monstertruck_brep/README.md)

---

## 1. Контекст и постановка проблемы

Цель проекта **MCP-CAD** — предоставить ИИ-агенту надёжную среду параметрического 3D-моделирования деталей и механизмов с автоматической верификацией геометрии (`validate_mesh`), расчётом прочности методом конечных элементов (`mcp-cad-fea`) и динамической симуляцией (`mcp-cad-physics`).

### 1.1. Текущее устройство геометрии (проверено по кодовой базе)

На текущий момент (ветка `agent/P1-T3`, после завершения `P0-T1..P0-T12`, `P1-T1`, `P1-T2`) геометрическое ядро `crates/mcp-cad-core` (суммарно **12 569 строк Rust-кода** в 13 модулях) устроено следующим образом:

1. **Представление геометрии (`topology.rs`, 620 строк):**
   - Единственным представлением твёрдого тела является поверхностная треугольная сетка `TriangleMesh { vertices: Vec<Vertex>, indices: Vec<[u32; 3]> }`.
   - Граничного аналитического представления (B-Rep: NURBS/аналитические поверхности, кривые, топологическая иерархия `Solid → Shell → Face → Wire → Edge → Vertex`) нет.
   - У треугольников отсутствуют идентификаторы граней (`face_ids`), поэтому после генерации примитива или булевой операции невозможно однозначно сослаться на «верхний торец цилиндра» или «стенку отверстия $\varnothing 20\text{ мм}$».
2. **Параметрические примитивы (`primitives.rs`, 4 143 строки; `dag.rs`, 838 строк):**
   - Генераторы `create_box`, `create_cylinder`, `create_cone`, `create_sphere`, `create_polygon_prism`, `create_spur_gear`, `create_wheel_rim`, `create_revolve`, `create_helical_cutter_with_settings` напрямую строят конформные триангулированные сетки с адаптивным 2-к-1 разрежением колец для прохождения строгого гейта качества углов (`Sliver Quality Gate`: `lt_1_deg_count == 0`, `lt_5_deg_ratio <= 1.0%`).
3. **Булевы операции (`csg.rs`, 2 783 строки):**
   - Реализованы собственным алгоритмом на двоичных деревьях разбиения пространства (BSP-trees в `f64`) с эвристиками слияния копланарных треугольников в выпуклые квады, 1-ring ear-clipping, Link-Condition edge collapse, Delaunay-флипами и «ремонтом» манифолдности (`repair_manifold_triangles`).
   - Несмотря на то что в рамках `P0-T7` базовые пары примитивов в `csg_invariants.rs` были стабилизированы, собственные BSP-деревья в `f64` с фиксированным допуском толщины плоскости `PLANE_EPSILON = 1e-5` имеют фундаментальные ограничения:
     - На задаче `T08_hex_nut_m10` (`cut_helical_groove`, см. [`docs/BENCH_BASELINE_RUST.md`](../BENCH_BASELINE_RUST.md) и `P3-T11`) вычитание винтовой нарезки из шестигранной заготовки гайки с отверстием разрушает водонепроницаемость (`is_watertight = false`, `open_boundary_edges = 615`, `genus = 98.0` вместо `1.0`).
     - На эталонной детали `P1-T3` (цилиндр $R=15, h=50\text{ мм}$ + бокс-фланец $40\times 40\times 10\text{ мм}$ минус соосное отверстие $\varnothing 20\text{ мм}$ при `segments = 64`) последовательность `csg_union` + `csg_difference` выполняется **`940.9 мс`** и оставляет **`24` открытых граничных ребра (`is_watertight = false`, $\chi = -8, g = 5.0$)**.
4. **Ограничения для ИИ-агента и FEA (`mcp-cad-fea`, 2 506 строк):**
   - В `run_fea_analysis` (`crates/mcp-cad-server/src/tools/fea.rs`) закрепления и нагрузки можно задать только по 6 граням габаритного параллелепипеда (`AabbFace::{MinX..MaxZ}`) или секущей плоскости. Агент не может закрепить внутреннюю поверхность отверстия под подшипник или приложить крутящий момент к конкретному торцу ступенчатого вала.
   - Отсутствуют операции скругления произвольных 3D-рёбер (`Fillet`), выдавливания произвольного 2D-эскиза с отверстиями (`ExtrudeSketch`) и экспорта в инженерный стандарт ISO 10303-21 `STEP`.

### 1.2. Ограничения проекта и лицензии (проверено)

- **Лицензия репозитория (`LICENSE`):** двойная пермиссивная лицензия **`Apache-2.0 OR MIT`** по выбору пользователя. Любая обязательная зависимость ядра с копилефт-лицензией (`GPL`, `LGPL-2.1` при статической линковке, `AGPL`) создаёт юридические ограничения при распространении единого бинарника `mcp-cad-server`.
- **Кроссплатформенность:** проект обязан собираться и запускаться на **Linux** (`run_server.sh`, `Dockerfile` на `rust:1.91-bookworm`, GitHub Actions CI) и **Windows** (`run_preview.bat`, `run_preview.ps1`).
- **Политика «Zero C++ / Pure Rust» (`README.md`):** в документации проекта заявлена архитектура `100% Pure Rust` без внешних C/C++ зависимостей в вычислительном ядре (**`[DECISION]`** — сохраняется ли это требование как жёсткий инвариант?).

## 2. Рассмотренные варианты геометрического ядра

Все сведения о внешних библиотеках ниже **проверены прямыми запросами к индексу `crates.io` (`cargo info`) и инспекцией исходного кода пакетов** в контейнере сборки 05.11.2026.

### Вариант A: Поверхностные сетки + устойчивое ядро Mesh Boolean (`manifold-rust`)

Сохранить архитектуру на основе треугольных сеток (`TriangleMesh`), заменив нестабильный BSP-CSG в `crates/mcp-cad-core/src/csg.rs` на промышленный алгоритм булевых операций класса **Manifold** (Emmett Lalish) с гарантией сохранения 2-манифолдности (watertightness) и встроенной трассировкой идентификаторов граней (`face_id`).

#### Доступные пакеты в Rust-экосистеме (проверено по `crates.io`):

1. **`manifold-rust` (`v0.19.2`)** — **основной кандидат Варианта A**:
   - **Описание:** Полный порт C++ библиотеки [Manifold v3.5.4](https://github.com/elalish/manifold) на **100% чистый Rust** (`build = false`, ни одной строки C/C++ или FFI), разработанный Lars Brubaker (MatterHackers).
   - **Источники:** [crates.io/crates/manifold-rust/0.19.2](https://crates.io/crates/manifold-rust/0.19.2), [github.com/larsbrubaker/manifold-rust](https://github.com/larsbrubaker/manifold-rust), [docs.rs/manifold-rust/0.19.2](https://docs.rs/manifold-rust/0.19.2).
   - **Лицензия:** **`Apache-2.0`** (полностью совместима с `Apache-2.0 OR MIT`).
   - **Требования к `rustc`:** `1.77+` (в нашем проекте `1.91.1`).
   - **Зависимости:** `clipper2-rust v1.0.3` (2D булевы операции и офсеты полигонов), `dashu-int v0.5.1` и `dashu-ratio v0.5.1` (точная целочисленная и рациональная арифметика произвольной точности для геометрических предикатов), `num-traits v0.2`, `rustc-hash v2.1`, опционально `rayon v1.10` (`features = ["parallel"]` с побитовой детерминированностью результата).
   - **Ключевые возможности (проверено по исходному коду `manifold-rust-0.19.2/src/`):**
     - Булевы операции `union`, `difference`, `intersection`, пакетная композиция и разрезание плоскостью с гарантией `Error::NoError` и замкнутости (`is_watertight == true`) на произвольных пересечениях.
     - Двойная точность `f64` без сужения типов через `MeshGL64` и обобщённый `MeshGLP<f64, u32>` (`Manifold::from_mesh_glp` / `get_mesh_glp`).
     - **Нативная поддержка именованных граней (`Topological Provenance`):** структура `MeshGLP<f64, u32>` содержит поля `pub face_id: Vec<u32>` (по одному ID исходной грани на каждый треугольник) и `pub run_original_id: Vec<u32>` (ID исходного примитива/операнда через `Manifold::reserve_ids`). Алгоритм триангуляции полигонов пересечения (`face_op_triangulate.rs`, `boolean_result_assemble.rs`) **автоматически наследует `face_id` и `run_original_id` для каждого дочернего треугольника результата булевой операции**.
     - 2D-сечения и эскизы (`CrossSection` на базе `clipper2-rust`): булевы операции над 2D-контурами с отверстиями, экструзия (`Manifold::extrude`), вращение (`Manifold::revolve`), скругление 2D-углов экструзии/вращения через `CrossSection::offset` (`JoinType::Round`), выпуклая оболочка (`Quickhull`), суммы и разности Минковского (`minkowski_sum`, `minkowski_difference`), генерация сеток по функции знакового расстояния (`Manifold::level_set_with_tolerance`).
2. **`manifold-csg` (`v0.4.1`) + `manifold-csg-sys` (`v3.5.105`)**:
   - **Описание:** Rust FFI-биндинги к оригинальному C++ ядру `manifold3d`.
   - **Источники:** [crates.io/crates/manifold-csg/0.4.1](https://crates.io/crates/manifold-csg/0.4.1), [github.com/zmerlynn/manifold-csg](https://github.com/zmerlynn/manifold-csg).
   - **Лицензия:** `Apache-2.0 OR MIT`.
   - **Недостаток относительно `manifold-rust`:** требует CMake и C++17 компилятор при сборке (`manifold-csg-sys`), тогда как `manifold-rust v0.19.2` даёт тот же алгоритм v3.5.4 на чистом Rust без C++ тулчейна.
3. **`boolmesh` (`v0.2.2`)**:
   - **Описание:** Независимая реализация манифолдных булевых операций на чистом Rust (`rust-version = 1.88`).
   - **Источники:** [crates.io/crates/boolmesh/0.2.2](https://crates.io/crates/boolmesh/0.2.2), [github.com/komietty/boolmesh](https://github.com/komietty/boolmesh).
   - **Лицензия:** `MPL-2.0` (слабый копилефт). Уступает `manifold-rust` по зрелости, скорости и отсутствию встроенного `face_id` / `CrossSection` / `SDF`.
4. **`csgrs` (`v0.20.1`)**:
   - **Описание:** Булевы операции на BSP-деревьях в Rust.
   - **Источники:** [crates.io/crates/csgrs/0.20.1](https://crates.io/crates/csgrs/0.20.1), [github.com/timschmidt/csgrs](https://github.com/timschmidt/csgrs).
   - **Лицензия:** `MIT`. Использует тот же класс BSP-деревьев, что и наш текущий `csg.rs`, и подвержен тем же проблемам численной робастности на касательных/винтовых пересечениях.

### Вариант B: B-Rep ядро на основе OpenCascade через C++ биндинги (`opencascade-rs`)

Перевести геометрическое ядро на промышленное C++ B-Rep ядро **OpenCASCADE Technology (OCCT 7.8)** через Rust-обёртки.

#### Доступные пакеты в Rust-экосистеме (проверено по `crates.io`):

- **`opencascade` (`v0.3.0`)**, **`opencascade-sys` (`v0.3.0`)**, **`occt-sys` (`v7.8.1`)**:
  - **Источники:** [crates.io/crates/opencascade/0.3.0](https://crates.io/crates/opencascade/0.3.0), [crates.io/crates/occt-sys/7.8.1](https://crates.io/crates/occt-sys/7.8.1), [github.com/bschwind/opencascade-rs](https://github.com/bschwind/opencascade-rs).
  - **Лицензия:** **`LGPL-2.1`** (соответствует лицензии OCCT; статическая линковка через feature `builtin` в `occt-sys` накладывает требования LGPL-2.1 на распространяемый бинарник и конфликтует с чистой лицензией `MIT` репозитория).
  - **Возможности:** Полный стек B-Rep (точные аналитические цилиндры, конусы, сферы, торы, B-сплайны и NURBS), промышленные булевы операции (`BRepAlgoAPI_Fuse/Cut/Common`), честные 3D-скругления и фаски (`BRepFilletAPI_MakeFillet`, `BRepFilletAPI_MakeChamfer`), лофтинг, шеллинг, чтение/запись `STEP` и `IGES`.
  - **Стоимость сборки и риски:**
    - `occt-sys v7.8.1` компилирует миллионы строк C++ исходников OpenCascade через `cmake`: холодная сборка занимает **15–40 минут**, требует C++ компилятора (`g++`/`clang++`/`MSVC`), `cmake` и системных заголовков на Linux и Windows.
    - Нарушает архитектурное ограничение `Zero C++ / Pure Rust`.
    - Высокоуровневый крейт `opencascade v0.3.0` покрывает лишь часть API OCCT и давно не обновлялся на `crates.io`, поэтому для продвинутых операций (топологическое именование `TNaming`, инспекция кривизны, настройка `BRepMesh_IncrementalMesh`) потребуется писать собственные `unsafe` FFI-обёртки поверх `opencascade-sys`.

### Вариант C: Чистый Rust B-Rep (`truck` / `monstertruck`)

Перевести геометрическое ядро на нативное Rust B-Rep ядро с аналитическими/NURBS поверхностями и явной топологией `Solid → Shell → Face → Wire → Edge → Vertex`.

#### Доступные пакеты в Rust-экосистеме (проверено по `crates.io`):

1. **Оригинальный стек `truck` (`ricosjp/truck`):**
   - `truck-modeling v0.6.0`, `truck-shapeops v0.4.0` (булевы операции), `truck-meshalgo v0.4.0` (тесселяция), `truck-stepio v0.3.0` (STEP I/O).
   - **Источники:** [crates.io/crates/truck-modeling/0.6.0](https://crates.io/crates/truck-modeling/0.6.0), [github.com/ricosjp/truck](https://github.com/ricosjp/truck).
   - **Лицензия:** **`Apache-2.0`**.
   - **Ограничение:** в оригинальном `truck` отсутствует модуль 3D-скруглений рёбер (`fillet`), а разработка оригинального репозитория замедлилась.
2. **Активный форк `monstertruck` (`virtualritz/monstertruck`, `v0.4.1`) — исследован в Spike 2:**
   - **Состав стека:**
     - [`monstertruck-modeling v0.4.1`](https://crates.io/crates/monstertruck-modeling/0.4.1) — построение B-Rep тел (`builder::vertex`, `line`, `circle`, `rect`, `cuboid`, `extrude`, `revolve`, `revolve_wire`).
     - [`monstertruck-solid v0.4.1`](https://crates.io/crates/monstertruck-solid/0.4.1) — булевы операции над B-Rep (`or`, `and`, `difference`, `symmetric_difference`, `plane_cut`).
     - [`monstertruck-fillet v0.4.1`](https://crates.io/crates/monstertruck-fillet/0.4.1) — скругления рёбер методом катящегося шара (`fillet_edges`, `fillet_along_wire`, постоянный и переменный радиус `RadiusSpec::{Constant, Variable, PerEdge}`, работает в том числе пост-CSG по рёбрам `IntersectionCurve`).
     - [`monstertruck-meshing v0.4.1`](https://crates.io/crates/monstertruck-meshing/0.4.1) — триангуляция B-Rep оболочек (`triangulation`, `robust_triangulation`) и анализаторы сетки.
     - [`monstertruck-io v0.4.1`](https://crates.io/crates/monstertruck-io/0.4.1) — чтение и запись **ISO 10303-21 STEP** (`AUTOMOTIVE_DESIGN` AP214) и чтение IGES 5.3.
   - **Источник:** [github.com/virtualritz/monstertruck](https://github.com/virtualritz/monstertruck).
   - **Лицензия:** **`Apache-2.0`** (100% Pure Rust, без C++).

## 3. Результаты экспериментальных прототипов (`spikes/`)

В соответствии с заданием `P1-T3` созданы два изолированных прототипа вне основного workspace (со своими `Cargo.toml`, без модификации кода `crates/*`):
1. **`spikes/manifold_rust/`** — проверяет **Вариант A** (`manifold-rust v0.19.2`) и на тех же входных сетках сравнивает его с **Вариантом D** (текущий `mcp-cad-core` BSP-CSG).
2. **`spikes/monstertruck_brep/`** — проверяет **Вариант C** (`monstertruck v0.4.1`: B-Rep булевы операции, `FaceID`/`EdgeID`, скругление ребра `R=2 мм` через `monstertruck-fillet`, тесселяцию и экспорт `STEP`).

### 3.1. Описание эталонной детали

- **Базовый цилиндр:** $R_{\text{out}} = 15\text{ мм}$, $h = 50\text{ мм}$ ($z \in [-25, +25]\text{ мм}$).
- **Минус соосное сквозное отверстие:** $\varnothing 20\text{ мм}$ ($R_{\text{in}} = 10\text{ мм}$).
- **Плюс бокс-фланец:** $40 \times 40 \times 10\text{ мм}$ ($z \in [-20, -10]\text{ мм}$) со сквозным центральным отверстием $\varnothing 20\text{ мм}$.
  - Точный аналитический объём фланцевой втулки (гладкие цилиндры):
    $$V_{\text{exact}} = \pi (15^2 - 10^2)\cdot 50 + (40^2 - \pi \cdot 15^2)\cdot 10 = 16\,000 + 4\,000\pi \approx 28\,566.3706\text{ мм}^3$$
  - Точный аналитический объём при 64-угольной аппроксимации цилиндра и отверстия:
    $$V_{64\text{-gon}} = 28\,546.1940\text{ мм}^3$$
- **Скругление ребра $R = 2\text{ мм}$:**
  - Аналитический объём после скругления 1 вертикального ребра фланца ($L = 10\text{ мм}$): $28\,557.7865\text{ мм}^3$.
  - Аналитический объём после скругления 4 вертикальных рёбер фланца ($4 \times 10\text{ мм}$): $28\,532.0343\text{ мм}^3$.
- **Площадь верхнего кольцевого торца ($z = +25\text{ мм}$, $R \in [10, 15]\text{ мм}$):**
  - Гладкое кольцо: $S_{\text{exact}} = \pi(15^2 - 10^2) = 125\pi \approx 392.6991\text{ мм}^2$.
  - 64-угольное кольцо: $S_{64\text{-gon}} = 392.0686\text{ мм}^2$.

### 3.4. Ключевые технические выводы из прототипов

1. **Почему Вариант D (текущий BSP-CSG) больше не масштабируется:**
   - Даже после всех улучшений `P0-T7` последовательное выполнение `csg_union` + `csg_difference` на 64-сегментной фланцевой втулке занимает майже **1 секунду (`940.9 мс`)** и **нарушает замкнутость сетки (`24` открытых граничных ребра, род `5.0` вместо `1.0`)**.
   - На внутренней метрической резьбе `T08_hex_nut_m10` (`P3-T11`) текущий BSP-CSG оставляет **`615` открытых рёбер** (`genus = 98.0`).
   - В то же время `manifold-rust v0.19.2` выполняет ту же операцию на фланцевой втулке за **`25.0 мс`** (а на нативных примитивах — за **`5.0 мс`**, в **188 раз быстрее**), а на гайке `T08_hex_nut_m10` — за **`18.9 мс`**, давая **абсолютно водонепроницаемую сетку (`0` открытых рёбер, `0` неманифолдных рёбер, `genus = 1.0`)** в обоих случаях.
2. **Почему Вариант C (`monstertruck` B-Rep) не может заменить сеточное ядро целиком на текущем этапе:**
   - **Скорость булевых операций:** трассировка кривых пересечения NURBS-поверхностей (`marching-ssi`) на простой втулке с фланцем занимает **`834 мс`** (в **33–166 раз медленнее** `manifold-rust`), а на сложных многозаходных резьбах (`cut_helical_groove`), зубчатых венцах (`create_spur_gear`, 20–40 эвольвентных зубьев) и колёсных дисках (`create_wheel_rim`) приводит к многосекундным задержкам или ошибкам сходимости `ShapeOpsError`.
   - **Качество тесселяции для FEA и Sliver Gate:** штатный триангулятор `monstertruck-meshing` (`spade` в 2D параметрической области $(u,v)$) на подрезанных NURBS-гранях генерирует **`21 416` треугольников**, из которых **`1 327` имеют минимальный угол `< 1°` (`min_angle = 0.002°`), а доля треугольников `< 5°` составляет `11.76%`** (при допустимом пороге проекта `<= 1.0%`). Такая сетка не проходит `validate_mesh` и непригодна для гранично-согласованного МКЭ (`P3-T5`).
   - **Сброс `FaceID` при булевых операциях:** `FaceID` в `monstertruck-topology` является указателем `Arc` (`0x557706af5cf0` до булевой операции $\to$ `0x557706b33fe0` после), то есть `monstertruck-solid` не сохраняет историю происхождения граней автоматически.
   - **Сильные стороны `monstertruck`:** нативное B-Rep скругление рёбер (`monstertruck-fillet` отрабатывает за `3.8–7.3 мс` даже по кривым пересечения цилиндра с фланцем!) и мгновенный экспорт в `STEP` (`1.25 мс`).
3. **Готовая инфраструктура для задач `P2-T5..T8` (именованные грани) в `manifold-rust`:**
   - В `manifold-rust` каждый треугольник входного `MeshGLP<f64, u32>` несёт пользовательский `face_id: u32`, а каждый примитив — `run_original_id: u32`. После произвольной цепочки `union` / `difference` / `intersection` выходной `MeshGLP` содержит точный `face_id` родительской грани для каждого треугольника. На прототипе верхний кольцевой торец (`face_id = 101`) был извлечён после двух булевых операций без единой геометрической эвристики с площадью **`392.0686 мм²` (ошибка `0.0000%` к 64-угольному кольцу)**.

2. **Радикально упрощает и ускоряет блок задач `P2-T5..T8` (Именованные грани):**
   - Вместо сложной и хрупкой ручной проброски `face_id` сквозь рекурсивное разбиение полигонов BSP-деревом и фазу `repair_manifold_triangles` (`P2-T7`, оценённая в `L`), `manifold-rust` уже содержит промышленный механизм `MeshGLP::face_id` и `run_original_id`, сохраняющий идентификаторы граней с точностью до `0.0000%` по площади (подтверждено в `spikes/manifold_rust`). ## 8. Риски и способы их минимизации

1. **Риск №1 — Игольчатые треугольники (`< 1°`) вдоль линий пересечения криволинейных сеток в `manifold-rust`:**
   - *Наблюдение на прототипе:* на фланцевой втулке до постобработки `manifold-rust` даёт `0.89%` треугольников `< 5°` (укладывается в порог `1.0%`), но создаёт `16` узких треугольников с углом `< 1°` (`min_angle = 0.303°`) там, где вершины 64-угольного цилиндра близко подходят к плоской грани фланца.
   - *Минимизация:* прогонять выход `Manifold` через уже написанный и протестированный в `P0-T7` конвейер `optimize_csg_mesh_quality` (копланарные флипы Делоне, Link-Condition схлопывание коротких рёбер с сохранением `face_id` и тангенциальная релаксация).
2. **Риск №2 — Расхождение допусков сварки вершин между `TriangleMesh` и `Manifold`:**
   - *Наблюдение на прототипе:* `TriangleMesh` хранит дублирующиеся вершины на острых рёбрах (для раздельных нормалей `Vertex.normal`), тогда как `Manifold` требует топологически сваренную 2-манифолдную сетку по индексам. При слишком жёстком допуске (`1e-9` м) микро-расхождения координат после поворотов могут препятствовать склейке.
   - *Минимизация:* в `P1-K1` использовать в конвертере `TriangleMesh -> MeshGLP` точно ту же пространственную сетку сварки `(diag * 1e-7).max(1e-12)` с проверкой окрестности $3\times 3\times 3$, которая используется в `validate_mesh` (`diagnostics.rs:224-255`), а при экспорте `MeshGLP -> TriangleMesh` восстанавливать нормали по группам `face_id` (гладкие внутри цилиндрических/сферических `face_id`, жёсткие на стыках разных `face_id`).
3. **Риск №3 — Отсутствие общего 3D B-Rep rolling-ball скругления произвольных пространственных кривых в чистом сеточном ядре:**
   - *Минимизация:* 90% машиностроительных скруглений (скругления контуров фланцев, кронштейнов, пазов, галтели валов вращения `revolve`, скругления рёбер боксов/призм) точно решаются через 2D-скругление эскиза (`CrossSection::offset`), скругление профиля `revolve` или фасонный CSG-резец. Если в будущем потребуется полное 3D-скругление по пересечению произвольных NURBS, оно может быть добавлено модульно через `monstertruck-fillet` (`Вариант A+C`).
