## 4. Остаточные риски и заметки по выполнению `P2-T2`

- При реализации `P2-T2` добавление нового MCP-инструмента `set_units` увеличит общее число инструментов в `tools::list_tools()` с `28` до `29`. Необходимо синхронно обновить контрактную проверку количества инструментов в `crates/mcp-cad-server/tests/mcp_contract_tests.rs`.
- Поскольку bestaande контрактные тесты в `crates/mcp-cad-server/tests/mcp_contract_tests.rs` и `qa_wide_scan.rs` передают размеры в метрах (`0.1`, `0.05`), при переключении дефолта `EngineState::new()` на `LengthUnit::Mm` в `P2-T2` следует явно вызывать `set_units({"length_unit": "m"})` в старых метрических фикстурах либо параметризовать их, плюс добавить новые контрактные тесты эквивалентности `"mm"` vs `"m"`.

## 5. Побочные находки (занесены в `TASKS.md` как `P2-T15`, не исправлялись в рамках `P2-T1`)

В ходе построчного аудита размерных констант обнаружены два дефекта, зарегистрированные в `TASKS.md` под номером **`P2-T15`**:

1. **Потенциальная паника `f64::clamp(min, max)` (`min > max`) в `create_wheel_rim_with_settings` при диаметре диска `< 140.3 мм` (`crates/mcp-cad-core/src/primitives.rs:3052`)**:
   - На строке `3052` вычисляется `let d_pcd = pcd_diameter.unwrap_or((d_hub + d_bore) * 0.5).clamp(d_bore + 0.015, d_hub - 0.012);`.
   - Так как по умолчанию `d_hub = d_rim * 0.35` и `d_bore = d_hub * 0.45 = d_rim * 0.1575`, при `d_rim < 0.1403 м` (`140.3 мм`) нижняя граница `d_bore + 0.015` оказывается больше верхней границы `d_hub - 0.012`, что вызывает панику `f64::clamp` во время выполнения.
2. **Применение мотора к вращательной оси `JointAxis::AngX` вместо `JointAxis::LinX` при вызове `set_joint_motor` для призматического шарнира (`crates/mcp-cad-physics/src/simulator.rs:219-231`) и несогласованность единиц `limits` в `create_joint` (`crates/mcp-cad-server/src/tools/physics.rs:248-259`)**:
   - В `Simulator::set_joint_motor` (`simulator.rs:223-224`) для любого уже существующего шарнира в `impulse_joint_set` вызывается `joint.data.set_motor_velocity(JointAxis::AngX, ...)` вместо проверки типа шарнира (`JointAxis::LinX` для `JointDesc::Prismatic`), из-за чего мотор на поступательном шарнире не работает при установке через `set_joint_motor`.
   - В `create_joint` параметр `limits: [min, max]` для вращательного шарнира (`revolute`) передаётся в Rapier3D напрямую как радианы (`rad`), хотя во всех остальных инструментах MCP углы задаются в градусах (`deg`), и в описании схемы (`tools/mod.rs:390`) единицы не указаны.
