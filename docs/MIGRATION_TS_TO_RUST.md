## 0. Резюме аудита и расхождение с `docs/DECISIONS.md`

В `docs/DECISIONS.md` (ADR-001: *Unified Rust Engine & Thin Web UI*, ADR-002: *Unified Port 3000 & Localhost Security Boundary*) архитектура «Unified Rust Engine + Thin Web UI over REST/SSE» описана как **уже принятая и реализованная**. Фактическая проверка кодовой базы показала обратное:

1. **Два независимых CAD/CSG/FEA/Physics/Optimizer/MCP движка сосуществуют и расходятся**:
   - **Rust Workspace** (`crates/mcp-cad-{core,fea,physics,viewer,server}`): **14 078 строк** в `src/` + **3 598 строк** в `tests/` (всего **17 676 строк** Rust). Все исправления геометрии и топологии из `P0-T1..P0-T12` (копланарное слияние граней BSP, Делоне-флипы, `cut_helical_groove` с полусферическими торцами, инварианты ориентации граней `revolve` и `wheel_rim`) внесены **только в Rust**.
   - **TypeScript Engine** (`src/cad/*.ts` + `src/types/cad.ts`): **9 909 строк** в `src/cad/*.ts` (`8 407 строк` без тестов + `1 502 строки` в `cad_engine.test.ts`) + **283 строки** в `src/types/cad.ts`. Весь клиентский код + бенчмарк (`src/` + `bench/`) составляет **18 695 строк** TypeScript/TSX.
2. **UI (`src/App.tsx`, 1 739 строк) работает поверх TS-движка по умолчанию (`engineRuntimeMode = 'ts_fallback'`)**:
   - Все интерактивные действия в браузере (создание деталей, изменение параметров в инспекторе, булевы операции, расчёт МКЭ с визуализацией полей напряжений/перемещений, живая кинематика, Query Optimizer, экспорт/импорт STL) вызываются напрямую из `src/cad/primitives.ts`, `src/cad/fea_solver.ts`, `src/cad/kinematics.ts`, `src/cad/query_optimizer.ts`, `src/cad/mcp_dispatcher.ts`.
   - Режим `native_windows_rust` в `src/App.tsx:266-318` делает лишь частичное зеркалирование (`executeRemoteWindowsMcpTool` на `http://127.0.0.1:8080/message`), но **после ответа Rust-сервера всё равно пересчитывает геометрию, FEA и кинематику локально в TypeScript**, так как Rust-сервер возвращает только текстовые/числовые JSON-сводки MCP без вершинных буферов `positions`/`normals`/`indices` и без узловых полей МКЭ.
3. **Заявленные в ADR-001/ADR-002 HTTP/SSE маршруты в Rust-сервере отсутствуют**:
   - В `crates/mcp-cad-server/src/sse.rs` (98 строк) реализованы **только два маршрута**: `GET /sse` и `POST /message` на захардкоженном адресе `127.0.0.1:8080` (`main.rs:34`, `sse.rs:89`).
   - Маршруты `/api/state`, `/api/events`, `/api/mcp`, раздача статики `dist/`, а также флаги CLI `--host` и `--auth-token`, упомянутые в `docs/DECISIONS.md`, в коде `crates/mcp-cad-server` **не существуют**.

## 3. Необходимые HTTP/SSE endpoints на Rust-сервере для работы UI без TS-движка

### 3.1. Что реально есть сейчас в `crates/mcp-cad-server`
В `crates/mcp-cad-server/src/sse.rs` (строки 29–46) сейчас зарегистрированы только два маршрута:
- `GET /sse` — открывает SSE-стрим протокола MCP (отправляет `event: endpoint\ndata: /message` и транслирует JSON-RPC ответы от `POST /message`).
- `POST /message` — принимает JSON-RPC 2.0 запрос (`initialize`, `tools/list`, `tools/call`) и возвращает `Json<Option<JsonRpcResponse>>`.

**Почему этого недостаточно для работы Web UI (`src/App.tsx` и `CadViewport3D.tsx`) без TS-движка:**
1. `tools/call` в MCP возвращает человекочитаемые и агентские JSON-сводки (количество вершин, объём, массу, `max_von_mises_stress_pa`), но **не возвращает массивы геометрии** (`positions: Float32Array`, `normals: Float32Array`, `indices: Uint32Array`, `boundaryEdgePositions: Float32Array`), без которых `CadViewport3D.tsx` не может построить `THREE.BufferGeometry`.
2. `run_fea_analysis` в Rust не возвращает скалярное поле напряжений и векторное поле перемещений на вершинах поверхностного меша детали (`feaStressMPa`, `feaDisplacements`), без которых не работает тепловая карта фон Мизеса и слайдер деформации (`deformScale`) во вьюпорте.
3. Когда внешний MCP-клиент (например, Claude Desktop или агент через `POST /message`) создаёт или изменяет деталь, UI не получает структурированного уведомления об изменении сцены и не имеет эндпоинта для загрузки текущего состояния `EngineState`.
4. Браузерные функции «Import STL» (`<input type="file">`) и «Export STL» (скачивание `.stl` файла через браузер) не могут читать/писать произвольные пути на файловой системе сервера и требуют передачи байтов по HTTP.

### 3.2. Спецификация целевых HTTP/SSE маршрутов в `crates/mcp-cad-server`

Для полного удаления вычислительного TS-движка (`src/cad/primitives.ts`, `csg_bsp.ts`, `fea_solver.ts`, `kinematics.ts`, `query_optimizer.ts`, `mcp_dispatcher.ts`) Rust-сервер (`crates/mcp-cad-server/src/sse.rs`) должен предоставлять следующие маршруты на едином порту (по умолчанию `3000` для Web UI + MCP, с поддержкой `--port` и `--host`):

| № | Метод и маршрут | Формат ответа | Назначение для Thin Web UI |
|---:|:---|:---|:---|
| 1 | `POST /message` и `POST /api/mcp` | `application/json` (JSON-RPC 2.0) | Выполнение всех 28 MCP-инструментов и `tools/list` как для внешних AI-агентов, так и для панели MCP Tool Runner в UI. После любой мутации публикует событие `state_updated` в SSE-канал `/api/events`. |

## 4. Пошаговый план миграции (шаги размером `<= 1 задача агента`)

Каждый шаг спроектирован так, чтобы выполняться **за одну задачу агента**, не ломать сборку (`cargo test`, `npm run build`) и сохранять работоспособность UI на каждом промежуточном этапе:

### Шаг 1 (`P1-T2a`): Унификация контрактов 28 MCP-тулов и ID материалов между Rust и UI
- **Объём работ**:
  1. В `crates/mcp-cad-core/src/material.rs`: добавить поддержку алиасов коротких ID материалов из UI (`steel_1045` → `steel_structural_aisi1020`, `steel_4140` → `steel_high_strength_4140`, `alu_6061` → `aluminum_6061_t6`, `ti_6al_4v` → `titanium_grade5_ti6al4v`, `pla_3d` → `pla_filament_3dprint`, `petg_3d` → `petg_filament_3dprint`), добавить `borosilicate_glass` и опциональные PBR-метаданные (`color_hex`, `roughness`, `metalness`, `category`).
  2. В `crates/mcp-cad-server/src/tools/{cad,fea,physics,metrics,render}.rs`: поддержать синонимы параметров, используемые клиентом (`id`/`name` в `register_material`, `material_id`/`material_name` в `set_part_material`, `node_index`/`feature_id` в `modify_feature_param` и `suppress_feature`, `part_a_id`/`part_b_id` в булевых операциях и `measure_distance`), а также исправить откат `physics_world` в `batch_cad_operations` и сохранение `!part.is_fixed` при перерегистрации детали в `physics_world`.
- **Критерии приёмки**:
  - Все контрактные тесты `cargo test -p mcp-cad-server --test mcp_contract_tests` проходят.
  - Любой вызов из `MCP_TOOLS_CATALOG` в UI успешно выполняется на Rust-сервере без ошибок `Missing parameter`.

### Шаг 2 (`P1-T2b`): Реализация REST/SSE/Binary endpoints в `crates/mcp-cad-server` (ADR-001 & ADR-002)
- **Объём работ**:
  1.
