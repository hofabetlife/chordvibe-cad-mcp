## P0-T1 — Исправить ориентацию торцевых крышек (цилиндр, конус, шестерня, обод)

**Размер:** M | **Зависит от:** — | **Ветка:** `agent/P0-T1`

### Контекст (проверено измерением)
- `create_cylinder(1.5, 5.0, 64)` даёт `signed_volume() = 11.83` при аналитическом `35.34`. Разложение вклада по нормалям: боковая стенка +23.52 (верно, это ≈ 2/3·V), крышки −11.69 (должно быть ≈ +11.78). Крышки перевёрнуты.
- При `segments = 8` (крышка — просто веер центр→кольцо, без колец) объём 31.8198 совпадает с точным значением для 8-угольной призмы. Значит, ломаются кольцевые полосы, а не финальный веер.
- Подозреваемые функции в `crates/mcp-cad-core/src/primitives.rs`: `add_bridged_ring_strip_2d` (~строка 121), `add_halving_ring_transition_2d` (~187), вызывающая их `add_subdivided_disk_cap_2d` (~229). Кольца идут против часовой стрелки при взгляде с +Z.
- В `add_bridged_ring_strip_2d` комментарий утверждает, что порядок `[a_i, a_next, b_next, b_i]` (a — внешнее кольцо, b — внутреннее) даёт нормаль −Z, и потому для `is_top` порядок разворачивается. Проверь это расчётом по формуле шоулейса на одном секторе: по оценке при подготовке этот порядок даёт +Z, то есть разворот лишний. Не принимай мою оценку на веру.
- Прежний аудит связывает регрессию с коммитом `6db3344` («fix(core): eliminate sliver triangles…»): `git show 6db3344 -- crates/mcp-cad-core/src/primitives.rs`. Цель того коммита — убрать иглы в крышках; это свойство нужно сохранить.
- Крышки строятся одной функцией, вызываемой из `create_cylinder` (~341), `create_cone` (~796, крышки ~815–836), шестерни (~1676) и других мест: `grep -n add_subdivided_disk_cap_2d`.
- `TriangleMesh::signed_volume()` (`topology.rs:257`) = Σ v0·(v1×v2)/6; для замкнутой сетки с нормалями наружу > 0. `volume()` берёт `abs()` и маскирует переворот.

### Задача
Найди и исправь неверный порядок вершин в кольцевых полосах и переходах крышек так, чтобы все треугольники крышек были ориентированы наружу (нормаль +Z для верхней, −Z для нижней), не ухудшив качество треугольников.

### Критерии приёмки
1. Эти тесты проходят:
   - `cargo test -p mcp-cad-core --lib` → `diagnostics::tests::test_validate_mesh_cylinder_pass`, `primitives::tests::{test_cylinder_volume, test_cone_sharp_volume, test_cone_frustum_volume, test_spur_gear_solid_volume_and_dimensions}`
   - `cargo test -p mcp-cad-core --test dag_tests` → `test_primitive_volumes_analytical_verification`, `test_dag_cone_and_frustum_volume`
   - `cargo test -p mcp-cad-core --test tessellation_tests` → `test_cylinder_adaptive_tessellation_density_and_convergence`
   - `cargo test -p mcp-cad-server --test qa_wide_scan` → `test_bug_002…`, `test_bug_004…`, `test_bug_007…`
2. Добавь unit-тест `cap_orientation_*` рядом с существующими в `primitives.rs`: для цилиндра, конуса, усечённого конуса и шестерни геометрическая нормаль каждого треугольника верхней крышки имеет `n·(+Z) > 0`, нижней `n·(−Z) > 0`, а `signed_volume()` в пределах 1% от аналитического.
3. `validate_mesh` на этих примитивах не выдаёт «Orientation is inconsistent».
4. Доля треугольников крышек с минимальным углом < 5° не выросла по сравнению с поведением до исправления (укажи способ измерения в отчёте).
5. В отчёте — список тестов, которые всё ещё падают после исправления, и по одной строке про причину каждого (это вход для P0-T3).

### Не делать
Не менять пороги sliver gate. Не менять `volume()` или `signed_volume()`, чтобы скрыть переворот. Не трогать другие примитивы и CSG (кроме случая, когда это прямое следствие этого же дефекта, — тогда опиши).

### Задача

Для каждого примитива и сетки параметров (радиусы 0.001…0.1 м, разные отношения высота/радиус, segments ∈ {0 (авто), 8, 16, 32, 64, 128}, многоугольники 3…12 сторон, шестерни 8…40 зубьев, профили revolve: прямоугольник и L-образный) проверяй:

4. `signed_volume() > 0` и отличается от аналитического значения не более чем на допуск (для многоугольной аппроксимации сравнивай с точной формулой многоугольной призмы либо допускай 1–2%).
5. Ограничивающий параллелепипед совпадает с заданными размерами в пределах 1e-9 относительно масштаба.

### Критерии приёмки

- Если инвариант выявил НОВЫЙ дефект, не чини его здесь: оформи отдельным тестом `known_bug_<что>` с `#[ignore = "BUG: <описание>"]` и внеси в таблицу в отчёте (параметры, ожидание, факт). Это единственный допустимый случай использования `#[ignore]`.

## P0-T4 — Контракт ошибок: тест BUG-016

**Размер:** S | **Зависит от:** — | **Ветка:** `agent/P0-T4`

### Контекст (проверено)
- Валидация профиля revolve в Rust-сервере УЖЕ есть: `crates/mcp-cad-server/src/tools/cad.rs` ~строки 305–390 (отрицательный r, самопересечение, угол ∈ (0,360], segments ≥ 3). Прежний отчёт ошибочно утверждал, что её нет.
- Тест `test_bug016_revolve_boundary_and_self_intersection_validation` (`tests/mcp_contract_tests.rs`, ~строки 2400–2440) падает на `assert!(neg_r_resp.get("error").is_some(), …)`: он ждёт верхнеуровневое поле JSON-RPC `error`.
- Сервер (`protocol.rs`, ветка `"tools/call"`, ~строки 217–237) превращает `Err(ServerError)` в `ToolCallResult::error(...)` с `result.isError = true` и текстом ошибки. Это соответствует конвенции MCP: ошибки выполнения инструмента — внутри `result` с `isError: true`, а JSON-RPC `error` — для протокольных ошибок (неизвестный метод, неверная структура запроса).

### Задача
1. Проверь `grep -n 'get("error")' crates/mcp-cad-server/tests/*.rs` и пойми, какую конвенцию применяют остальные тесты.
2. Приведи тест BUG-016 (и любые другие, ждущие JSON-RPC `error` для ошибок инструментов) к контракту сервера: введи общий helper `assert_tool_error(&resp)`, проверяющий `result.isError == true` и непустой текст.
3. Зафиксируй контракт в `docs/MCP_API_REFERENCE.md` (раздел «Ошибки»): что считается ошибкой инструмента, что протокольной.
4. **[DECISION]** Неизвестное имя инструмента сейчас даёт `isError` (через `ServerError::ToolNotFound`), а по спецификации MCP это протокольная ошибка. Не меняй поведение; опиши в отчёте как рекомендацию.

### Критерии приёмки
- `cargo test -p mcp-cad-server --test mcp_contract_tests test_bug016` проходит; остальные тесты файла не ухудшились.
- Тест не стал слабее: он по-прежнему проверяет все три случая (r<0, самопересечение, угол).

### Не делать
Не менять `protocol.rs` и валидацию в `cad.rs`.
