## P1-T1 — План миграции TS→Rust (ADR-001 не выполнен)

**Размер:** M | **Зависит от:** — | **Ветка:** `agent/P1-T1` | **Только документ, без изменения кода**

### Контекст (проверено)
- `docs/DECISIONS.md`, ADR-001: выбран «Вариант Б» — единый Rust-бэкенд `mcp-cad-server` (`SharedState = Arc<RwLock<EngineState>>`), а клиент остаётся тонким; ADR прямо требует удалить из TypeScript вычислительные модули `primitives.ts`, `csg_bsp.ts`, `fea_solver.ts`, `kinematics.ts`, `query_optimizer.ts`.
- Фактически все они на месте в `src/cad/` (`primitives.ts` ≈116 КБ, `mcp_dispatcher.ts` ≈49 КБ, `fea_solver.ts` ≈30 КБ, `query_optimizer.ts` ≈33 КБ, `csg_bsp.ts`, `kinematics.ts`, `workbenches.ts`, `materials.ts`, `native_bridge.ts`). UI импортирует их: `src/App.tsx` (7 импортов), `components/CadRightSidebar.tsx` (4), `CadViewport3D.tsx`, `CadTitleBar.tsx`, `CadQueryOptimizerPanel.tsx`, `CadLeftSidebar.tsx`.
- `src/cad/native_bridge.ts` содержит режимы `windows_exe_connected` и `unified_hybrid_kernel`, адрес по умолчанию `http://127.0.0.1:8080`.
- `bench/run_benchmark.ts` вызывает `executeMcpToolOnEngineState` из `src/cad/mcp_dispatcher` — то есть бенчмарк исполняет TS-движок, а не Rust-сервер, которым пользуется агент.
- В TS есть упоминания TET10 (`src/cad/fea_solver.ts`, `src/types/cad.ts`), в Rust TET10 нет (только предупреждение в `convergence.rs`). Заявления бенчмарка про TET10 к Rust-серверу не относятся.
- Rust-сервер: stdio по умолчанию, `--port N` — HTTP/SSE; по ADR есть эндпоинты `/api/state`, `/api/events`, `/message` (проверь по `crates/mcp-cad-server/src/main.rs` и `grep -rn "route(" crates/mcp-cad-server/src`).

### Задача
Подготовь `docs/MIGRATION_TS_TO_RUST.md`:
1. Инвентаризация: для каждого файла `src/cad/*.ts` — что дублирует в Rust (файл/функция), кто его импортирует, что уникально (нет аналога в Rust — вынеси отдельным списком).
2. Матрица паритета: инструменты MCP (28) × [есть в Rust / есть в TS / расхождения поведения]. Найди расхождения по именам и параметрам (сравни `tools/mod.rs` и `src/cad/mcp_dispatcher.ts`).
3. Какие HTTP/SSE-эндпоинты Rust-сервера нужны UI, чтобы работать без TS-движка (состояние детали, меши, события), и каких не хватает.
4. Пошаговый план миграции из шагов не более «одной задачи агента» каждый, с критериями приёмки и порядком. Шаги не должны ломать UI.
5. **[DECISION]** Что делать с TS-тестами `cad_engine.test.ts` (1502 строки): удалить, портировать в Rust или оставить как контрактные тесты клиента.

### Критерии приёмки
Документ содержит все 5 пунктов; каждая ссылка на код проверена (файл существует, функция найдена); план не опирается на неверифицированные утверждения (помечай «не проверено»).

Шаги и инструменты берутся из `tasks.json` как есть. Для каждой задачи фиксируй: успех вызовов, водонепроницаемость, ошибка габаритов, для T11–T15 отклонение от аналитики.

## P1-T3 — ADR: выбор геометрического ядра **[DECISION]**

**Размер:** M | **Зависит от:** — | **Ветка:** `agent/P1-T3` | **Результат — документ и прототипы, не изменение основного кода**

### Контекст
Сейчас геометрия — только треугольные сетки (`TriangleMesh`); тела описываются мешем и DAG-историей. Булевы операции — BSP-деревья по сетке (`crates/mcp-cad-core/src/csg.rs`, 1282 строки, с эвристиками «ремонта» манифолдности). Следствия: нет B-rep, нет именованных граней и рёбер, нет скруглений (`TASKS.md` TASK-007 «ExtrudeSketch», TASK-008 «Fillet» не реализованы), закрепления и нагрузки в FEA задаются только гранями ограничивающего параллелепипеда (`AabbFace::{MinX…MaxZ}`) или плоскостью. README заявляет «Zero C++ / Pure Rust». Лицензия репозитория — двойная (в начале файла `LICENSE`: Apache-2.0 или…; уточни вторую). Есть запуск под Windows (`run_preview.bat/.ps1`) и Linux (`run_server.sh`).

Цель проекта: ИИ-агент должен ссылаться на геометрию по смыслу («торец вала», «поверхность отверстия Ø10») и надёжно получать корректные тела.

### Задача
Подготовь `docs/adr/0001-geometry-kernel.md`: сравнение вариантов
- A: остаться на мешах, но заменить BSP-CSG на устойчивые меш-булевы (например, библиотеки класса Manifold; уточни, что на самом деле доступно в Rust-экосистеме и на какой лицензии);
- B: B-rep на основе зрелого ядра через биндинги (например, OpenCascade; C++-зависимость);
- C: чистый Rust B-rep (например, `truck`);
- D: оставить текущий BSP и доводить.

Критерии сравнения (оцени каждый вариант по каждому): надёжность булевых операций, именованные грани/рёбра («topological naming»), фаски/скругления/выдавливание эскиза, экспорт STEP/STL, качество тесселяции для FEA и рендера, стоимость сборки на Windows и Linux, лицензия, зрелость и поддержка, нужный объём миграции (сколько кода в `mcp-cad-core`, `fea`, `physics`, `viewer`, `server` затронуто), совместимость с политикой «Pure Rust» (**[DECISION]** — это ограничение сохраняется?).

Для двух лучших кандидатов сделай прототип в отдельном каталоге вне workspace (`spikes/<имя>/`, свой Cargo.toml, не трогая основной): цилиндр R=15 мм, h=50 мм минус коаксиальное отверстие Ø20 мм, плюс бокс-фланец, затем (если поддерживается) скругление ребра R=2 мм; получи объём (сверь с аналитическим), число треугольников, время, проверку замкнутости, и можно ли получить имя/идентификатор грани торца.

### Критерии приёмки
- ADR содержит таблицу вариантов×критериев, рекомендацию, оценку работ по миграции в задачах (список с размерами), риски и открытые вопросы к человеку.
- Любое утверждение о библиотеке (возможности, лицензия, версия) подтверждено источником (ссылка) либо помечено «не проверено». Если нет доступа в сеть — так и напиши и опиши, что нужно проверить.
- Прототипы запускаются командой, указанной в `spikes/<имя>/README.md`; результаты замеров в ADR.
